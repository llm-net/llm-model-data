## API 参考要点（`media-wan3-api`）

- 「HTTP 调用 → 步骤1」：`POST https://{WorkspaceId}.<region>.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`（北京 cn-beijing 及新加坡、东京、法兰克福、弗吉尼亚、香港）。请求头 `X-DashScope-Async` 必选且须为 `enable`，「HTTP 请求只支持异步」，缺少报「current user api does not support synchronous calls」。步骤2 查询 `GET …/api/v1/tasks/{task_id}`；task_id 与结果链接有效期 24 小时，过期返回 `UNKNOWN`。
- `model`：`wan3.0-video-prime`「高速版，能力对齐标准版，端到端速度显著提升」；`wan3.0-video`「标准版」。全文没有按型号区分的参数或取值。
- `input.prompt`：与 `media` 必填其一；「每个汉字/字母占一个字符，不超过20000个字符，超过部分会自动截断」；可用「图1」「视频1」「音频1」指代 media 顺序。
- `input.media[]`：`type` + `url`。`first_frame` ≤1、`last_frame` ≤1、`reference_image` ≤10、`reference_video` ≤5 且总时长 ≤15 秒、`reference_audio` ≤5 且总时长 ≤15 秒、`file` ≤1、`link` ≤1（二者互斥）。
  - 图像：JPEG、JPG、PNG（不支持透明通道）、BMP、WEBP；单边 [240, 8000] 像素；长宽比不超过 8:1；「文件大小：不超过20MB」；公网 HTTP/HTTPS URL、`oss://dashscope-instant/…` 临时 URL、`data:{MIME_type};base64,…`。
  - 视频：mp4、mov；单个 [1, 15] 秒、总时长不大于 15 秒；帧率 ≥16 fps；单边 [240, 4096]；长宽比不超过 8:1；「单文件大小：不超过100MB」；仅公网 URL 或 oss 临时 URL。
  - 音频：wav、mp3；单个 [1, 15] 秒、总时长 ≤15 秒；「文件大小：不超过15MB」；仅 URL。
  - 文件：docx、doc、xlsx、xls、pptx、ppt、pdf、txt、key、pages、numbers、md；「不超过100MB」；≤50 页。网页链接：无需登录的公开网页。
- `parameters`：`resolution` 缺省 1080P，可选 1080P / 720P / 480P；`ratio` 缺省 adaptive，另 21:9、16:9、4:3、1:1、3:4、9:16；`duration` 缺省 5，无视频输入 [2, 30]，有视频输入时输入视频总时长 + 输出时长 ≤30，`-1` 智能时长；`audio` 缺省 true（开关同价）；`seed` 取 -1 或 [0, 2147483647]，传 -1 或未指定时随机；`prompt_extend` 缺省 true，传 file / link 时必须为 true；`watermark` 缺省 false。
- 查询响应：`output.video_url`（成功时），「视频URL仅保留24小时」；`usage.video_count` 固定 1、`duration`、`input_video_duration`、`output_video_duration`、`fps`（默认 30）、`SR`、`ratio`。
- 「素材组合」：文生视频只传 prompt；first_frame / last_frame 与 reference_* / file / link 互斥；file 与 link 二选一，可与 reference_* 组合；reference_* 之间自由组合；视频编辑、视频延长都必须含 reference_video，可与 reference_image / reference_audio 组合，靠提示词意图区分。示例：「视频延长 … 需将 ratio 设为 adaptive」。
- 「常见问题」：3.0 首帧 / 首尾帧模式不能同时传音频等其他素材。

## 使用指南要点（`media-wan3-guide`）

- 「模型能力」表：`wan3.0-video / wan3.0-video-prime` 是 All-in-One 模型，无需切换模型名，按 `input.media` 的 type 与提示词意图自动路由：文生视频、首帧、首尾帧、全模态参考（图 / 视频 / 音频及组合）、文件 / 网页生视频、视频编辑（提示词含「编辑视频」「去掉」「替换」「改成」等）、视频延长（「延长」「延续」「续写」「向前 / 向后延长」等）。
- 「输出视频」：分辨率 480P、720P、1080P（默认）；宽高比同 API；「时长：2~30秒；-1（智能时长，默认5秒）。有视频输入时，输入+输出总时长≤30秒」；「格式：MP4，帧率30fps」；有声视频默认开启；「视频URL有效期24小时」。
- 「全模态参考生视频」：「最多传入20个参考素材（图片、视频、音频、文档、网页）」。

## 模型价格（`pricing`）

「万相3.0-视频生成」小节华北 2（北京）表：`wan3.0-video-prime` 与 `wan3.0-video` 都列 480P / 720P / 1080P 三档，输入和输出视频秒均计费。只用于确认两型号分辨率档位相同，价格不在本次范围内。

## 逐模型结论

| 模型 | media_io | 操作 | 说明 |
| --- | --- | --- | --- |
| `wan3-0-video` | partial | text_to_video、image_to_video、first_last_frame_to_video、reference_to_video、video_edit、video_extend（均 `POST /api/v1/services/aigc/video-generation/video-synthesis`，async_task） | 字段、取值、缺省与上限按 API 参考逐项记录；输出 mp4、url、TTL 86400、30fps、≤30 秒。 |
| `wan3-0-video-prime` | partial | 同上 | API 参考写「能力对齐标准版」，指南与价格表也未列差异，契约与标准版相同。 |

- 编辑 / 延长的原视频记为 `source_video`，字段仍是 `input.media[type=reference_video].url`。
- 无视频输入的 `parameters.duration` 取值 `[-1, 2..30]` 放在共享取值集 `wan3-duration-no-video`，缺省 5；有视频输入的三项操作只记上限 30 与说明。
- `header:X-DashScope-Async` 记为必填参数（取值 `enable`）。

## 冲突

- 文件格式：API 参考列 12 种（含 key、pages、numbers）；指南「输入素材」表只列 9 种。按 API 参考写入 notes。
- 视频延长的 ratio：API 参考示例写「需将 ratio 设为 adaptive」，指南写「建议 adaptive」。未收窄取值，两处原文写入参数 notes。
- 指南「单次最多 20 个参考素材」与 API 参考各 type 上限之和（10+5+5+1=21）不一致；各 type 上限按 API 参考记录，20 写入 notes。
- 指南「-1（智能时长，默认5秒）」与 API 参考「默认值为5」：按 API 参考记缺省 5。

## 缺项与规范限制

- 文档（file）与网页链接（link）素材在 MEDIA-IO role 词表中没有对应角色，只写在 `reference_to_video` 的 notes；因此状态为 partial。
- 有视频输入时 duration 的下限依输入时长而变，且 -1 与区间无法用同一参数结构表达。
- 文件大小只有「20MB / 100MB / 15MB」原文，文档未写 MB 与字节的换算，按规范不记 `file_size`，原文写入各输入 notes。
- 各分辨率档位对应的像素值、seed 的字面缺省值未公布。
- wan3.0 文档没有 `negative_prompt`、`img_url`、`size` 等早期万相字段，未记录。
